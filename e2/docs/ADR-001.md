# ADR-001: 用异步 Job 模式处理四类耗时任务

- **Status**: Accepted
- **Date**: 2026-09-20
- **Authors**: A10 组

## Context

四类任务（DRAFT / BuildChecker / EChecker / MDFixer）单次执行可能从 5 秒到 30 分钟不等。
HTTP 客户端通常不会保持连接这么久；同步实现还会让客户端与服务端紧耦合。
课程约束：四类任务必须在统一接口下表达，且不允许长连接。

## Decision

采用 **异步 Job 模式**：

1. 客户端 `POST /v1/<task>-jobs` 创建任务
2. 服务端**立即**返回 `HTTP 202 Accepted` + `job_id`
3. 客户端用 `GET /v1/jobs/{job_id}` 轮询状态与结果
4. 同一次平台流程用 `trace_id` 串联

## Alternatives

### 方案 B：同步请求-响应
- ✅ 实现简单
- ❌ 长任务会断链、超时无解
- ❌ 客户端必须挂起

### 方案 C：Webhook 回调
- ✅ 客户端不轮询
- ❌ 服务端要公网可达地址
- ❌ 课堂环境做不到

## Consequences

### 正面
- HTTP 生命周期可控
- 客户端可并发提交多个 job
- 任务状态可追溯

### 代价
- 需要任务存储（演示用内存 Map 即可）
- 客户端需要轮询逻辑（演示用 `sleep 1s`）
- 需要严格的状态机（六态：QUEUED/RUNNING/SUCCEEDED/FAILED/TIMED_OUT/CANCELLED）
