**本人的代码修改。** 新增 `labs/e11e12/test_contract_221900015.py`，6 个用例：

1. `macro` 风格：补丁必须落在 `DEPS = ...` 变量行，且不新增规则行；
2. `mixed` 风格：补丁落在 `main.o: main.c $(HEADERS) ...` 规则行，保留 `$(HEADERS)`；
3. `direct` 风格：补丁落在规则行本身；
4. `patch()` 自带 STALE_REPORT 守卫：即使绕过 envelope 校验，旧报告也被拒绝且 Makefile 不变；
5. `UNSAFE_PATH`：`../escape.h`、`/etc/passwd`、`with space.h` 三种依赖均在写盘前被拒；
6. `snapshot()` 的 profile 边界：删掉 `helper.c/config.h` 后返回 `UNSUPPORTED_PROJECT`。

**缺陷的实际代价（`cost-demo.log`）。** 在真实项目的干净副本里：`make app` 成功后把 `config.h` 的 `VALUE` 从 1 改到 2，再 `make app` 得到 `make: 'app' is up to date.`，运行 `./app` 仍打印 `1`；只有 `touch main.c` 后才重新编译并打印 `2`。这就是缺 `config.h` 这条边在生产里的表现——改头文件不重编、二进制与源码不一致。
