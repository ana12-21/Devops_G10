# ADR：E11–E12 依赖检查与证据组织

状态：已用于本地实验；日期：2026-11-10；作者：杨宗乔（241880515）。

## 背景

全量检测覆盖编译与链接，而增量检查以 main.o/helper.o 为对象目标；不同提交的报告不能混用。服务器外网访问不稳定，且多人共享服务器，需要隔离个人目录与分支并保留可复查记录。

## 决策及理由

1. 复用团队 fixture 派生项目和固定提交历史，个人运行目录独立。适配教学 scan 的目标范围，避免把不受支持的任意项目运行结果解释为检测正确。
2. 比较全量与增量结果时使用一致的对象目标投影；保留全量原报告与增量报告，不因投影丢弃原始证据。
3. 采用教学实现的全局保守缓存键。函数体变化可复用；预处理指令、配方或工具链变化触发刷新。它牺牲部分复用率换取实现简单和保守失效，不宣传为逐目标精确失效。
4. 在修复前校验报告的 schema、kind、status 和 commit；个人测试重点验证 STALE_REPORT。正确报告与旧报告成对验证，避免只检验抛异常而漏掉正常路径。
5. 使用相对 artifact URI、SHA256 和 job/trace 标识组织输出；幂等键绑定请求摘要，同键异请求返回409。保留失败结果，重试使用新输出目录。
6. 为 E12 单独增加 Dockerfile.broken 并保存适配提交；保留基础镜像契约和摘要约束。只更换下载源，不放宽签名或依赖哈希验证。
7. Git 跟踪代码、请求来源说明和个人文档；work 证据及本地数据单独归档。数据仓库用 bundle 保留提交历史；不依赖共享服务器绝对路径作为唯一来源。

## 影响与边界

检测范围受教学 profile 限制，扫描不是通用 C 项目分析器。SHA 校验能发现字节变动，不能单独证明项目来源可信或运行可复现。接口级负例测试不替代端到端故障注入。镜像源可用性、GitHub 代理隧道和 CI 网络状态仍影响重新运行。

## 验证

见个人报告、运行索引、原始 work 日志：14 项单测通过；真实 E12 五阶段成功；幂等复用与409冲突通过；候选补丁三方哈希一致。PR/CI 和服务恢复尚待单独记录。
