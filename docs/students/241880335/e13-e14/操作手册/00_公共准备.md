# 公共准备：接续 E11–E12

所有 shell 命令在 SSH 登录后的 Linux 仓库根目录执行。先按 E11–E12 的 `02_操作手册/00_公共准备.md` 建好环境；不要把整个旧实验包反复覆盖到已有仓库。本轮云机没有 `unzip`。**E11–E12 分发 ZIP 的中文目录名采用 GBK 字节且未标 UTF-8，直接用 `python3 -m zipfile -e` 会解出乱码目录，不能用它判断 `03_实验包` 不存在。**若 E11–E12 已按前期手册导入并通过 `build/test/prepare`，直接继续本页；否则先按下方兼容步骤提取入口和代码。

```bash
python3 - <<'PY'
from pathlib import Path
import zipfile
archive = Path.home() / 'DevOps_E11_E12.zip'
root = Path.home() / 'devops-materials/DevOps_E11_E12/03_实验包'
prefix = 'DevOps_E11_E12/03_实验包/'
with zipfile.ZipFile(archive) as z:
    for item in z.infolist():
        name = item.filename.encode('cp437').decode('gbk')
        if name != prefix + 'run_e11e12.py' and not name.startswith(prefix + 'labs/e11e12/'):
            continue
        dest = root / name[len(prefix):]
        assert dest.resolve().is_relative_to(root.resolve())
        if item.is_dir():
            dest.mkdir(parents=True, exist_ok=True)
        else:
            dest.parent.mkdir(parents=True, exist_ok=True)
            dest.write_bytes(z.read(item))
PY
ls -l "$HOME/devops-materials/DevOps_E11_E12/03_实验包/run_e11e12.py"
```

此命令只提取入口和 `labs/e11e12`，不把分发包预生成的 `data/` 覆盖进个人仓库。导入时若 `git diff --cached --check` 指出 `labs/e11e12/environment/README.md` 行尾空白，将该文件的 CRLF 统一为 LF 后再暂存；不要跳过检查。旧仓库的 `.gitignore` 未必包含 E11 分发包中的 `data/` 规则。本轮 A、B 两组复跑时都实际出现了 `?? data/`，可在个人仓库根目录按下方检查并补齐：

```bash
if ! git check-ignore -q data/integration-sample; then
  printf '\n# E11-E12 generated local data\ndata/\n' >> .gitignore
fi
git add .gitignore
git diff --cached --check
git status --short
```

若只有 `.gitignore` 变更，提交后应再次确认 `git status --short` 为空。`data/` 下的固定样例与 API 临时数据仍保存在磁盘；配对真实项目的来源、请求和提交 SHA 应放在约定的可追踪位置，不能因忽略规则漏交。

```bash
pwd
git status --short
git rev-parse HEAD
git remote -v
python3 run_e11e12.py test
```

记录本次源码完整 SHA、镜像标签和 E12 成功目录。若 `git status --short` 有改动，先辨认其来源并保存；不要直接清空。选一份 E12 成功结果核对 `result.json` 的五阶段和 `recheck.json`，再用新的 `work/` 子目录运行，保留旧证据。

```bash
python3 run_e11e12.py run --request data/integration-sample/e12.json --out work/e13-baseline-01
echo "BASELINE_EXIT_CODE=$?"
```

这是固定样例回归，只证明现有链路仍能跑通。交叉测试必须另用对方提供的项目和完整提交 SHA。当前 E11–E12 项目适配范围是双 C 源文件、显式 Make 规则和预期程序输出 `1`；不符合该范围时应先记录 `UNSUPPORTED_PROJECT`，扩展适配和测试后再评价算法正确性。

双方交换：项目仓库地址、base/target 完整 SHA、Dockerfile 候选来源、预期输出、运行限制和数据集说明。不要交换 `.env`、真实 Key、云服务器密码或个人令牌。跨服务器 API 联调沿用 E12 的 SSH 本地端口转发，不开放公网 8080。

项目可以从课程 C/Make 样例发展而来，不要求学生自行寻找外部数据集。用于正式交换时，A/B 各自在本组仓库保留自己的修改、测试和提交；报告写清教师样例来源与本组新增内容。两份原封不动的生成样例互换只能做教师或学生的流程彩排。
