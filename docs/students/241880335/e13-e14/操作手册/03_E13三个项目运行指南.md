# E13 三个测试项目运行指南

本指南在 E13 测试阶段随项目包发放。三个项目分别来自 jsmn、inih 和 tiny-AES-c 的固定上游提交。项目包中的 `upstream-original/` 是原始上游文件，`repo/` 是接入本课程 E12 双源码流程的独立 Git 测试仓库。请在本组已有 E11–E12 环境的服务器上操作。

## 1. 解压与核对

把 `e13-upstream-student.zip` 上传到本组仓库根目录。在 SSH 登录后的仓库根目录运行：

```bash
(
  set -e
  test -f run_e11e12.py
  test -f e13-upstream-student.zip
  test ! -e data/e13-upstream-student
  python3 -m zipfile -t e13-upstream-student.zip
  python3 -m zipfile -e e13-upstream-student.zip data
)
for name in H1-jsmn H2-inih H3-tiny-aes; do
  printf '%s\n' "$name"
  git -C "data/e13-upstream-student/$name/repo" log -2 --format='%H %s'
  sed -n '1,3p' "data/e13-upstream-student/$name/repo/UPSTREAM.md"
done
```

看到两个完整的课程提交号以及上游链接后，保存终端输出。若 `data/e13-upstream-student` 已存在，请保留原目录并先核对来源；不要覆盖已有测试结果。

## 2. 为三个项目生成请求

以下命令从每个独立 Git 仓库读取 C0/C1 提交号，写入各自的请求文件。要求本组仓库在容器内挂载为 `/course`，与 E11–E12 的 `run_e11e12.py` 入口一致。

```bash
python3 - <<'PY'
import json
import subprocess
from pathlib import Path

root = Path('data/e13-upstream-student')
for name in ('H1-jsmn', 'H2-inih', 'H3-tiny-aes'):
    folder = root / name
    commits = subprocess.check_output(
        ['git', '-C', str(folder / 'repo'), 'rev-list', '--max-count=2', 'HEAD'],
        text=True,
    ).splitlines()
    assert len(commits) == 2, name
    target, base = commits
    request = {
        'mode': 'e12',
        'repo': '/course/' + (folder / 'repo').as_posix(),
        'base': base,
        'target': target,
        'candidate': '/course/' + (folder / 'candidate.Dockerfile').as_posix(),
        'expected_output': '1',
        'build_timeout': 600,
    }
    output = folder / 'request-e12.json'
    assert not output.exists(), output
    output.write_text(json.dumps(request, indent=2) + '\n', encoding='utf-8')
    print(name, 'base=', base, 'target=', target, 'request=', output)
PY
```

`expected_output` 是本课程构建验证入口需要的程序输出参数；是否找到正确依赖、补丁是否可接受，要看运行证据。三个请求和三个结果必须分开记录。

## 3. 逐个运行并记录

先运行 H1；确认命令结束并保存退出码后，把 `CASE` 依次改为 `H2-inih`、`H3-tiny-aes`，每项只运行一次。请使用全新的输出目录。

```bash
CASE=H1-jsmn
mkdir -p work
(
  set -e
  test ! -e "work/e13-$CASE-01"
  python3 run_e11e12.py run \
    --request "data/e13-upstream-student/$CASE/request-e12.json" \
    --out "work/e13-$CASE-01" \
    > "work/e13-$CASE-01.console.log" 2>&1
)
printf '%s_EXIT=%s\n' "$CASE" "$?"
python3 - "$CASE" <<'PY'
import json
import sys
from pathlib import Path

name = sys.argv[1]
p = Path('work') / ('e13-' + name + '-01') / 'result.json'
result = json.loads(p.read_text(encoding='utf-8'))
print('status=', result['status'])
print('stages=', [stage['name'] for stage in result['stages']])
print('target=', result.get('target_commit'))
print('error=', result.get('error'))
PY
```

对每项保存请求文件、完整提交号、退出码、`result.json`、原始构建和运行日志、报告与补丁验证记录。若失败，保留该任务目录，记录失败阶段和错误码，再在新目录做修复后的复测。`data/` 或 `work/` 即使被 Git 忽略，也要按课程提交要求另外交付证据。
