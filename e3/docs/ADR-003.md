# ADR-003: C0/C1/C2 设计决策 + C2 实测偏差处理

- **Status**: Accepted
- **Date**: 2026-09-20
- **Authors**: A10 组
- **Scope**: A 组（EChecker 测试样本 C0/C1/C2）；依赖 E2 ADR-001（异步 Job）与 ADR-002（error/findings 分离）
- **Related**: PPT Slide 23-27、PPT Slide 28-29（隐式规则建议）、`fixtures/commits/{C0,C1,C2}/.git_info.txt`、`work/20260920-135225/comparison_table.md`

## Context

E3 EChecker 需要三个**真实**提交组成的演化序列：声明正确 → 引入 MD → 命令变化（普通 make 漏掉）。PPT Slide 23-27 给出了这三步的预期输出，但 PPT 没有规定：

1. 这三个 commit 的源码与 Makefile 应该由谁、怎样构造；
2. 在不同编译器（GCC / Clang）、不同平台（Windows / Linux）下，"普通 make 时间戳检查是否会漏掉命令变化"是否需要一致；
3. 当**实测结果与 PPT 预期不符**时，应该改记哪个版本号作为权威答案。

A10 在本地（Windows + MinGW + GCC 12.2）跑 `scripts/run_lab.py` 两次复跑（`work/20260920-134753/`、`work/20260920-135225/`）后发现：
- C0、C1 完全符合 PPT 预期；
- **C2 在 Windows + MinGW 实测下 clean build 输出 = 12（不是 PPT Slide 26 假设的 19）**，原因是 `config.h` 内的 `#define MODE  0`（带末尾空格）覆盖了命令行 `-DMODE=7`。

这条偏差会被 A 后续 E5/E8 的工具直接消费，必须在 ADR 里给出**决策**而不是只描述现象。

## Decision

### 决策 1：C0/C1/C2 用**合成 commit** 而不是外部开源项目

**Decision**：三步都是 A10 在 `fixtures/commits/{C0,C1,C2}/` 下用 `git init` + `git tag` 自构造的合成 commit，对应文件提前 check in，每个目录附 `.git_info.txt` 注明 `provenance = INSTRUCTOR_SYNTHESIZED`。

**理由**：
- E3 是**测试样本准备阶段**，目标是让 EChecker / MDFixer 能跑、能判断对错、能互相比较，不需要被外部项目演化历史绑死。
- 合成 commit 保证三步的**唯一变量**就是声明差异或命令差异，与 PPT Slide 23-26 的"controlled experiment"教学法对应。
- 每个目录的 `.git_info.txt` 写明 `based_on` 与 `parent_sha`，让 A 后续工具能定位到与自己 committed 的真实 SHA。

### 决策 2：以**实测结果**为权威答案，PPT 假设仅作为对照参考

**Decision**：当实测结果与 PPT 假设不一致时，**实测为权威**，但必须在三处同时落痕：
1. `evidence/build_c2.txt` 保留完整 stdout/stderr 原文；
2. `evidence/comparison_table.md` 写明差异与根因；
3. `work/<时间戳>/commit-C2.observations.json` 在 `verifies` 字段注明差异。

**理由**：
- E3 后续工具（E5/E8）会消费本仓库的 evidence，证据必须可机读、可复现。如果以 PPT 假设为权威，工具会按"19"去找 feature，结果永远找不到，等于伪造结论。
- ADR-002 已经明确：`MISSING` / `REDUNDANT` 是检测发现，不是工具失败；同理，**"PPT 假设与实测不符"也是检测发现**——报告要诚实标注。
- 复用 ADR-001 异步 Job 模式：每个 commit 的"clean + 增量"两条构建线对应 EChecker 的两个 SUCCEEDED Job，结论以实测 stdout 为准。

### 决策 3：C2 偏差的根因诊断——`config.h` 内的宏覆盖命令行宏

**Decision**：明确根因是**源码内 `#define MODE 0` 覆盖命令行 `-DMODE=7`**，GCC 通过 stderr 发出 `"MODE" redefined` 警告；本次实验保持 `config.h` 不动（不要"修复"成 `#ifndef MODE ... #endif`），让 C2 在 E5/E8 阶段被 EChecker 当作"命令变化被普通 make 漏掉"的**正面样本**。

**理由**：
- 这条偏差恰好就是 PPT Slide 26 想证明的现象——`CFLAGS` 变了，源文件 timestamp 没变，普通 make **只重链接**不重编，正好就是 EChecker 应该报警的"命令变化未触发重建"。
- 如果修掉 `config.h` 的硬编码，C2 就退化成 C1（干净 build = 12，命令行 -DMODE=7 起作用），**失去 EChecker 的检测意义**。
- 在 `compare_table.md` 与 `commit-C2.observations.json` 同时标注根因后，A 后续工具能据此正确分类——"C2 输出 12 ≠ 工具失败，是源码内宏覆盖命令行宏"。

## Alternatives

### 方案 B：用真实开源项目的 commit 序列代替合成 commit

- ✅ 更接近真实场景
- ❌ 三步的"唯一变量"控制会被项目的无关 commit 污染（如顺手改注释）
- ❌ 外部项目随时可能 force-push、删除分支、`HEAD` 不稳定
- ❌ E5/E8 工具的"对照 oracle"会随项目漂移，无法做回归测试

### 方案 C：把 C2 的 `config.h` 改为 `#ifndef MODE ... #endif`，让 PPT 假设成立
- ✅ PPT Slide 26 的"clean = 19"严格成立
- ❌ 失去"命令变化未触发重建"的样本意义——C2 的输出会变得跟 C1 完全一样
- ❌ EChecker 在 C2 上跑不出"命令变化"类报警，工具基线少一个分支
- ❌ 等于为了对齐 PPT 而牺牲了样本价值

### 方案 D：写两份 C2——一份保留硬编码（实测 = 12）、一份改 `#ifndef`（PPT = 19）
- ✅ 两边都对得上
- ❌ 多 1 个 commit 破坏 PPT Slide 23-26 的"C0/C1/C2"三步法
- ❌ 后续工具需要分清"C2-hardcoded"和"C2-clean"，文档负担加重

## Consequences

### 正面

- 合成 commit 让 E3 EChecker 有了**可机读、可复现**的 baseline（`evidence/build_c{0,1,2}.txt` + `.git_info.txt`）。
- "实测为权威 + 三处落痕"让工具消费方知道**何时可以信 PPT、何时必须信 evidence**。
- 保留 C2 的硬编码反而把"命令变化 vs 源文件变化"两类检测目标都覆盖了——C1 测 MD、C2 测命令变化被忽略。
- 复跑 reproducibility 验证通过：两次 `work/20260920-134753` 与 `work/20260920-135225` 在剔除 `ts` 字段后命令序列与 stdout 完全一致 → evidence 落到 README 指定路径后，A 后续工具能放心消费。

### 代价

- 必须解释"为什么实测 ≠ PPT"，否则评审者会以为是 bug。→ `evidence/comparison_table.md` 写明根因 + stderr 原文第 17 行；ADR 本文做权威决策。
- Windows + MinGW 与 PPT 假设的 Linux + GCC 在宏覆盖语义上有差异。→ `evidence/env_check.txt`（待补）记录本机 GCC 版本，让工具按手册复现。
- C2 偏差意味着 A 后续 EChecker 必须**多一类发现**："源码内宏覆盖命令行宏"。→ 在 E5 工具的 finding schema 加一条 `MACRO_OVERRIDE` 候选（暂未启用，登记于 ADR 遗留）。

### 遗留

- 是否要把 `MACRO_OVERRIDE` 加入 `task.schema.json` 的 findings.type 枚举（与 `MISSING` / `REDUNDANT` 平级）？需 E5 阶段决定，本 ADR 仅登记。
- `evidence/linux-verified/` 是否在 E3 结束前补一份 Linux GCC 复跑结果？本机环境无 Linux 容器，留为可选。
- `scripts/run_lab.py` 是否需要支持 `--cross-platform` 标志切换 MinGW / Linux 行为？留为 backlog（**T-111**），本次不做。
