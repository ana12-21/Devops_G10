# ADR-003: C0/C1/C2 设计决策

- **Status**: Accepted（决策 3 于同日修订，见 §修订记录）
- **Date**: 2026-09-20
- **Authors**: A10 组
- **Scope**: A 组（EChecker 测试样本 C0/C1/C2）；依赖 E2 ADR-001（异步 Job）与 ADR-002（error/findings 分离）
- **Related**: PPT Slide 23-27、PPT Slide 28-29（隐式规则建议）、`fixtures/commits/{C0,C1,C2}/.git_info.txt`、`evidence/comparison_table.md`

## Context

E3 EChecker 需要三个提交组成的演化序列：声明正确 → 引入 MD → 命令变化（普通 make 漏掉）。PPT Slide 23-27 给出了这三步的**预期输出**，但没有规定：

1. 这三个 commit 的源码与 Makefile 应该由谁、怎样构造；
2. "普通 make 的时间戳检查会漏掉命令变化"这一结论在不同平台（Windows / Linux）下是否需要一致；
3. 当**实测结果与 PPT 预期不符**时，以哪一边为权威答案。

T-105 第一版按"源码里写死 `#define MODE 0`"实现，实测发现两个问题：

- C2 clean build 输出 **12**，不是 PPT Slide 26 的 **19**（源码内的裸 `#define MODE 0` 覆盖了命令行 `-DMODE=7`，GCC 还报 `"MODE" redefined` 警告）；
- 更关键的是，那样改完之后 **C2 的增量输出和 clean 输出都是 12**。两个答案一样，就无法证明"make 漏掉了命令变化"——因为"make 没重编"与"重编了但结果碰巧相同"这两种情况在证据上无法区分。这等于把 C2 这条样本的检测价值抹掉了。

## Decision

### 决策 1：C0/C1/C2 用**合成 commit** 而不是外部开源项目

**Decision**：三步都是 A10 在 `fixtures/commits/{C0,C1,C2}/` 下用 `git init` + `commit` + `tag` 自构造的合成 commit，源码提前 check in，每个目录附 `.git_info.txt`，其中 `provenance = INSTRUCTOR_SYNTHESIZED`、`based_on` 说明构造依据。

**理由**：

- E3 是**测试样本准备阶段**，目标是让 EChecker / MDFixer 能跑、能判对错、能互相比较，不需要被外部项目的演化历史绑死。
- 合成 commit 保证三步的**唯一变量**就是声明差异或命令差异，对应 PPT Slide 23-26 的 controlled experiment 教学法。
- 为了让 `.git_info.txt` 里的 SHA 真正可用（Slide 5 "保存真实 SHA"），提交时间被固定为 `COMMIT_DATES` 常量，使 SHA 在任意机器上重跑都一样，**可独立 checkout 验证**，而不是只在生成它的那台机器上有意义。

### 决策 2：以**实测结果**为权威答案，PPT 假设作为对照

**Decision**：实测与 PPT 假设不一致时，**实测为权威**，但必须三处同时落痕：

1. `evidence/build_*.txt` 保留完整 stdout/stderr 原文；
2. `evidence/comparison_table.md` 写明差异与根因；
3. `work/<时间戳>/*.observations.json` 在 `verifies` 字段注明差异。

**理由**：

- 后续 E5/E8 工具会消费本仓库的 evidence，证据必须可机读、可复现。若以 PPT 假设为权威，工具会按"19"去找 feature，结果永远找不到，等于伪造结论。
- ADR-002 已明确：`MISSING` / `REDUNDANT` 是**检测发现**，不是工具失败；同理，"PPT 假设与实测不符"也是检测发现，报告要诚实标注。
- 复用 ADR-001 异步 Job 模式：每个 commit 的"增量 + clean"两条构建线对应 EChecker 的两个 SUCCEEDED Job，结论以实测 stdout 为准。

**边界（重要）**：这条决策的适用范围是"**样本正确、结论有分歧**"。本次 C2 的情况不属于这一类——是**样本本身有缺陷**（源码宏覆盖命令行宏），所以按决策 3 修订样本，而不是把缺陷当成偏差记录。判断顺序永远是：先确认样本是否符合 PPT 的意图，再决定要不要把分歧记成检测发现。

### 决策 3（修订版）：`config.h` 用 `#ifndef MODE` 守卫，C2 按真实迁移流程复现

**Decision**：

1. `fixtures/commits/{C0,C1,C2}/config.h` 的 `MODE` 一律写成 `#ifndef MODE / #define MODE 0 / #endif`，让 Makefile 的 `-DMODE=7` 能真正生效；
2. `scripts/run_lab.py` 的 C2 场景按**真实迁移**执行，而不是在干净目录里重跑一遍：
   - 用 **C1 的 Makefile** 构建 C2 源码 → 12（变更前状态）；
   - 换入 **C2 的 Makefile**（只改编译命令），跑普通 `make` → 12（漏检）；
   - `make clean` 后再 `make` → 19（全量构建才拾取新命令）。

**理由**：

- 修正后 C2 的**增量 12 / clean 19** 与 PPT Slide 26-27 完全一致，不需要再解释任何"实测偏差"。
- 增量与 clean 给出**两个不同答案**，才真正证明"普通 make 的时间戳检查漏掉了命令变化"；这正是 EChecker 要报警的场景，也是旧样本丢失掉的东西。
- 旧样本里 `-D` 被源码覆盖，本质是**样本写错了**（`config.h` 自己的注释都写着"C2 will override this via Makefile CFLAGS"，说明原意就是让命令行宏生效），不是平台差异，也不是值得保留的课程内容。

### 决策 4：证据文本由脚本生成，不手工抄写

**Decision**：`evidence/build_*.txt` 由 `scripts/render_evidence.py` 从 `work/<ts>/*.json` 生成；复现性比对由 `scripts/diff_reproducibility.py` 生成日志。

**理由**：

- 手工把 JSON 里的数字抄进叙述文件，是两份数据打架的唯一来源——本次正是因为手工写在 `evidence/` 里的数（12）与脚本实际落盘的数对不上，才回头查出样本缺陷。
- 生成物顶部注明"不要手工编辑"，改样本 → 重跑 → 重新生成，链路单向，评审时可以随时复算。

## Alternatives

### 方案 A（原决策 3，已否决）：保留 `config.h` 的裸 `#define`，把 12 当作"实测偏差"记入 ADR

- ✅ 不用改样本，文档工作量小
- ❌ C2 的增量与 clean 输出相同（都是 12），**无法证明 make 漏掉了命令变化**——样本失去检测价值
- ❌ 与 PPT Slide 26-27 的预期表直接冲突，评审时要把"为什么你的样本跑不出 PPT 的数"当主线来解释，本末倒置
- ❌ 会让下游误以为需要新增 `MACRO_OVERRIDE` 这类 finding（源码宏覆盖命令行宏），而这条在真实项目里极少见，属于被错误样本带出来的假需求

### 方案 B：用真实开源项目的 commit 序列代替合成 commit

- ✅ 更接近真实场景
- ❌ 三步的"唯一变量"控制会被项目的无关 commit 污染（顺手改注释、CI 配置）
- ❌ 外部项目随时可能 force-push、删分支，`HEAD` 不稳定，SHA 无法长期引用
- ❌ 工具的对照 oracle 会随项目漂移，无法做回归测试

### 方案 C：写两份 C2——一份保留硬编码（实测 12）、一份改 `#ifndef`（PPT 19）

- ✅ 两边都对得上
- ❌ 多 1 个 commit 破坏 PPT Slide 23-26 的"C0/C1/C2"三步法
- ❌ 后续工具要分清 `C2-hardcoded` 与 `C2-clean`，文档负担加重

## Consequences

### 正面

- C0/C1/C2 三组数值与 PPT Slide 24-27 的预期表**逐项一致**，不再有"实测偏差"需要解释。
- C2 同时覆盖两类检测目标：增量线证明"命令变化被普通 make 漏掉"，clean 线给出正确答案，两条线的差异本身就是告警依据。
- 合成 commit 的 SHA 因固定提交时间而**可复现**，`git checkout <sha>` 在任何机器上都能验证。
- 证据文本可一键重新生成，与原始 JSON 不会漂移。

### 代价

- 样本被改过一次，`fixtures/commits/*/.git_info.txt` 的 SHA 随之更新；文档里凡引用旧 SHA 的地方都必须同步（本次已全量重新生成 evidence 并核对）。
- 需要向评审解释"为什么改了样本"：答案在 §修订记录，属主动纠错，不是掩盖偏差。

### 遗留

- `evidence/linux-verified/`（Linux + strace 复跑）：本机为 Windows 宿主机且无可用容器，留为可选（**T-108**）。
- `scripts/run_lab.py` 的 `--cross-platform` 开关（**T-111**）：本次不做。
- `MACRO_OVERRIDE` finding 类型（**T-112**）：随决策 3 修订而**失效**——样本里不再存在宏覆盖，不需要这一类发现。保留登记以免后人重复提出。
